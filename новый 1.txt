2. **Нужна ли прямая поддержка MEX-файла** (скомпилированного бинарника bk_engine_mex.mexw64) дополнительно к стандартному calllib, для максимального удобства синтаксиса в MATLAB? - подробнее 

Разница между calllib (вызов чистой C DLL) и MEX-файлом (.mexw64) в MATLAB заключается в удобстве синтаксиса и накладных расходах (скорости) при вызове в плотных циклах.

1. Как работает стандартный calllib (C-интерфейс)
MATLAB загружает DLL «как есть» и на лету преобразует типы данных MATLAB в типы языка Си (маршалинг памяти).

Синтаксис в MATLAB: Приходится вручную работать с C-указателями (libpointer):


matlab
% Нужно объявлять буфер и оборачивать его в libpointer
outBuf = zeros(nModes * nElectrodes, 1);
pOut = libpointer('doublePtr', outBuf);
 
% Вызов функции через имя библиотеки
calllib('BK_Engine', 'BK_SolveResistivity', hSolver, rho_bh, rho_pz, rho_t, pOut, int32(totalValues));
 
% Извлечение данных из указателя
results = pOut.Value;
Накладные расходы: На каждый вызов calllib тратится 10–50 микросекунд только на упаковку/распаковку аргументов между MATLAB и DLL. Если в палетке $100,000$ точек, только оверхед вызовов calllib займет 3–5 секунд впустую.
2. Как работает MEX-модуль (.mexw64)
MEX (MATLAB Executable) — это скомпилированная библиотека, которая внутри использует заголовочные файлы MATLAB (mex.h). Для MATLAB эта функция выглядит как родная встроенная функция самого языка MATLAB (как sin, fft или inv).

Синтаксис в MATLAB (предельно чистый, привычный разработчику MATLAB):


matlab
% Создание солвера
hSolver = bk_mex('create', 'sonde_config.json');
 
% Фиксация геометрии
bk_mex('set_geom', hSolver, 0.108, 0.400);
 
% Расчет точки (возвращает стандартную матрицу MATLAB напрямую!):
results = bk_mex('solve', hSolver, 1.0, 10.0, 50.0);
 
% Или расчет сразу целого векторного массива (батча) в одну строчку:
results_all = bk_mex('solve_batch', hSolver, rho_bh_vec, rho_pz_vec, rho_t_vec);
Накладные расходы: 0.1 микросекунды (в 100–300 раз быстрее вызова calllib). Данные сразу ложатся в память mxArray без промежуточного копирования.
Сравнительная таблица
Критерий	Вариант А: Чистый calllib	Вариант Б: MEX-модуль (.mexw64)
Синтаксис MATLAB	Громоздкий (нужны libpointer, явные типы int32, doublePtr)	Нативный, в 1 строку (как обычная функция MATLAB)
Оверхед на вызов	10–50 мкс на каждую точку	< 0.1 мкс
Передача массивов	Требует явного выделения памяти и разыменования	Напрямую принимает и возвращает векторы и матрицы MATLAB
Параллелизм (parfor)	Требует loadlibrary на каждом воркере	Работает «из коробки» без дополнительных настроек
Зависимости сборки	Только BK_Engine.dll и bk_engine_api.h	Нужен компилятор C++ в MATLAB (mex -setup)
Рекомендованное архитектурное решение:
Ядро библиотеки собирается как чистая, независимая от MATLAB BK_Engine.dll (C API). Это позволит использовать ее в Delphi, C++, Python и других средах.
Для разработчика MATLAB пишется тонкая MEX-обертка (bk_engine_mex.cpp $\rightarrow$ bk_engine_mex.mexw64) размером в ~80 строк, которая просто транслирует вызовы из MATLAB в BK_Engine.dll.
Это дает одновременно:

Универсальность: чистая DLL для любых языков.
Максимальный комфорт и скорость для MATLAB: разработчик MATLAB вызывает понятную функцию без возни с C-указателями.
